## Purpose

Server-side конфигурация и запуск MCP-сервера invest-mcp: транспорт, окружение, токен и аккаунт, режим подтверждений, инструмент get_accounts.

## ADDED Requirements

### Requirement: Сервер принимает конфигурацию на старте
Сервер SHALL принимать конфигурацию через CLI-ключи и переменные окружения: --env (sandbox по умолчанию; prod требует явного указания), --token или YATIS_TOKEN (обязателен), --host и --port, --confirm|--no-confirm (по умолчанию --confirm), --hook (необязателен). При отсутствии обязательных значений или невозможности подключиться сервер SHALL завершиться с понятной ошибкой и ненулевым кодом выхода.

#### Scenario: Запуск с токеном из окружения
- **WHEN** сервер запускается с --env sandbox и переменной YATIS_TOKEN
- **THEN** сервер начинает слушать указанный host/port (по умолчанию 127.0.0.1:3001) по протоколу Streamable HTTP

#### Scenario: Отсутствие токена
- **WHEN** сервер запускается без --token и без YATIS_TOKEN
- **THEN** сервер завершается с ошибкой о не заданном токене и ненулевым кодом выхода

#### Scenario: Явный запрос боевого окружения
- **WHEN** сервер запускается с --env prod
- **THEN** сервер подключается к боевому API; при передаче --no-confirm дополнительно выводится предупреждение о риске

### Requirement: Разрешение единственного аккаунта на старте
Сервер SHALL разрешить единственный аккаунт при старте через get_accounts: если возвращается ровно один счёт — использовать его для всех торговых операций; если счетов ноль или больше одного — завершиться с ошибкой. Параметр выбора аккаунта не предусмотрен: на токене всегда ровно один счёт.

#### Scenario: Единственный счёт
- **WHEN** get_accounts возвращает ровно один счёт
- **THEN** сервер использует этот счёт для всех торговых операций

#### Scenario: Больше одного счёта
- **WHEN** get_accounts возвращает более одного счёта
- **THEN** сервер завершается с ошибкой (выбор аккаунта параметром не предусмотрен)

### Requirement: get_accounts
Сервер SHALL предоставлять инструмент get_accounts, возвращающий список счетов (id, тип, статус) текущего токена.

#### Scenario: Получение счетов
- **WHEN** вызывается get_accounts
- **THEN** возвращается список счетов с id, типом и статусом

### Requirement: Гейтинг торговых инструментов режимом подтверждений
В режиме --confirm сервер SHALL требовать параметр confirm=true у инструментов place_order, replace_order, cancel_order, place_stop_order, cancel_stop_order и возвращать ошибку при его отсутствии. В режиме --no-confirm подтверждение не требуется. Стратегии (run_strategy и lifecycle-инструменты) SHALL работать в обоих режимах без гейтинга.

#### Scenario: Отклонение без подтверждения
- **WHEN** сервер запущен с --confirm и вызывается place_order без confirm=true
- **THEN** инструмент возвращает ошибку о необходимости подтверждения, заявка не размещается

#### Scenario: Подтверждение принимается
- **WHEN** сервер запущен с --confirm и вызывается place_order с confirm=true
- **THEN** заявка размещается и возвращается результат

#### Scenario: Стратегии не гейтятся
- **WHEN** сервер запущен с --confirm и вызывается run_strategy
- **THEN** стратегия запускается без требования confirm
